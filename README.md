# Immich TV Private

面向自托管 Immich 的 Android TV 私用分支。基于 [giejay/Immich-Android-TV 6.2.0](https://github.com/giejay/Immich-Android-TV/tree/6.2.0)，基线提交 `90f879c3eba843c9d976505fc463d236d846bd91`。上游该标签的 Gradle 版本字段仍是 6.1.0/code147；本分支开发候选版本为 `1.3.0-private`，包名 `io.github.z979054461.immichtv`，可与原版共存，不覆盖原版。

## 运行时隐私边界

- 只手动输入自己的服务器 URL 和专用 API Key，无作者配对网站、演示服务器或第三方登录。
- 删除 Firebase Analytics/Crashlytics、Google 登录、Google Play 计费及捐赠入口，没有统计或崩溃上传。
- API、Glide 图片和 Media3 视频/屏保使用同一受限 HTTP 客户端。每次请求在 DNS/连接前检查配置的协议、域名、端口和 `/api/` 路径。
- **所有 HTTP 重定向均拒绝**。反向代理需要直接提供最终 HTTPS 地址，不能转到另一个域名、端口或路径。外部 CDN 媒体也不支持。
- API Key 仅在 `x-api-key` 请求头中，绝不加到图片/视频 URL。移除外部播放器和系统桌面相册频道，不把媒体凭据交给其他应用。
- 不记录响应、URL 或凭据，不配置任何 Timber 输出。密钥由 AndroidKeyStore AES-GCM 加密；加密失败则拒绝保存，没有明文降级。
- 禁止云备份和设备迁移提取应用数据。使用系统/用户证书信任库，**没有“忽略证书验证”选项**。
- HTTP 仅在用户确认风险后可配置。强烈推荐 HTTPS；应用不能使明文局域网连接变得安全。

“无第三方运行服务”指应用代码的服务请求不依赖作者或其他云服务；不意味着 Android 操作系统、输入法、DNS、路由器或用户配置的代理不联网。构建时仍需从 Google/Maven/Gradle/GitHub 下载开源依赖，这与运行时服务依赖不同。

## 功能

保留上游的遥控器导航、相册/人脸/时间线、照片及视频播放、幻灯片、前台屏保预览与元数据显示。深色电视界面采用统一卡片、对比清晰的遥控器焦点和多人选择页。手动连接界面提供中文，密钥遮罩、禁用输入框状态保存，并在离开界面时清空输入框。

### 多账户与本地 PIN

- 最多保存 12 个独立本地档案。每个档案填写昵称、自己的服务器地址、该 Immich 用户的专用 API Key，以及独立的 4 位数字 PIN；这不是服务器邮箱/密码登录，也不创建 Immich 账户。
- 冷启动、手动锁定、切换账户后需输入 PIN。每个档案可设置离开应用后的免 PIN 宽限：立即、1、5、15 分钟，默认 **5 分钟**；前台持续观看不被倒计时打断。成功添加档案也通过解锁入口进入，返回键不能进入上一个用户的页面。
- 宽限仅保存在本次进程内，以单调时钟计时；到期、进程/电视重启或 Activity 重建后重新输入 PIN。设置提供“立即锁定”。宽限期间，同一电视的其他使用者也能返回原账户；不希望这样可设为立即锁定。
- API Key 继续由 AndroidKeyStore AES-GCM 加密。PIN 不以明文保存，使用随机 16 字节 salt、600,000 次 PBKDF2-HMAC-SHA1、256 位摘要和恒定时间比较；SHA1 PRF 为兼容 Android 7/API24。第 5 次尝试后等待 30 秒，连续尝试递增至最多 5 分钟，计数与冷却时间跨进程保存。
- 即使仍在宽限内，离开应用也立即隐藏页面、停止媒体、清空活动网络会话和元数据状态。正常从电视桌面返回且宽限有效时，只恢复同一档案并创建全新网络会话；旧请求/响应和旧导航图不能复活。锁定或切换账户立即撤销宽限，系统最近任务截图被屏蔽。
- 共享 Glide 持久/内存缓存仍禁用；1.2 起另有账户和会话隔离的限额缩略图缓存，详见下方。照片后台系统屏保会立即硬锁并退出，即使尚在宽限内；解锁后的前台屏保预览仍可用。
- 从 1.0.0 升级需重新填写服务器和 API Key 并设置 PIN，不会将已有免 PIN 凭据交给任何首次打开电视的人绑定。服务器照片不受影响。
- 忘记 PIN 可删除该电视上的本地档案，再用 API Key 添加；不会删除服务器账户或照片。当地用户能够删除本地档案，但无法因此解锁原档案。

**PIN 只是电视应用的本地访问锁，不是 Immich 密码，也不能防御 root、应用数据被篡改或已泄露的 API Key。** 不要把 PIN 告诉他人；遗失/泄露 Key 应在自己的 Immich 中撤销。

### 1.1.1：四位 PIN 与时间线稳定性修复

- 新建档案使用 **4 位数字 PIN**，保留前导零。电视解锁采用三列遥控器数字盘，输入四位自动提交并立即显示“正在验证”，校验成功立即进入主页；不因 UI 看似无响应而重复提交。
- **已有 6–12 位 PIN 不会截短或清除**。先输入完整旧 PIN 并确认，再设置、确认新的四位 PIN。取消迁移保持原 PIN 和锁定状态。
- 验证仍使用上述 PBKDF2 和持久失败退避，不为加速而降低校验强度。600,000 轮派生及安全存储可能在电视 CPU 上耗时；即时反馈不等于无耗时验证。
- 修复首次布局尚未测得宽度时生成 1 像素照片网格、Leanback 在等待数据期间隐藏加载/错误提示、只查一个空月份便误判空图库、刷新后仍复用旧月份内容等问题。
- 初始连续空月份每批最多检查 6 个月；还有未检查月份时明确显示“继续检查”，不宣称整个图库为空。失败保留已加载内容与错误提示，刷新会真正重新拉取。
- 首图可操作时不再等待可选“回忆”接口；回忆为空/失败、刷新后旧照片消失、宿主晚绑定和续页取消都会正确释放或恢复遥控器焦点，不把界面永久锁住。

### 时间线空白与大型图库

时间线通过 Immich API 读取月份列表，再按需读取月份内容；不是网页嵌入，也不会在打开时下载全图库原图。已核对 Immich 3.3.5 的 `/api/timeline/buckets`、`/api/timeline/bucket`、`asset.read` 权限及参数。

时间线首次只读取月份索引和第一个有内容的月份；随着可见行/遥控器焦点接近底部，才读取后一个月份。跳到指定月份只取该月，焦点移动不再自动下载相邻月。缩略图由可见单元按需读取，不在进入时下载全部原图。

1.1.1 消除密集单日布局中逐项删除列表头的二次复杂度，改为单次线性遍历；翻页条件按实际剩余行数判断，避免“同一天上万张照片”被错误视为马上到达底部。焦点定位使用已建立的资产索引，不再每按一次方向键就构造整份照片列表。布局计算在后台线程执行。

**这是真实的按月滚动加载，不是每 N 张照片的服务器分页。** Immich 3.3.5 的月份接口一次返回整月，没有分页参数。其搜索分页的时间过滤与月份接口采用不同字段，且伴侣范围不同，不能简单替换而保证不漏照片、不改变范围。本版也还没有月份缓存的硬内存上限，长时间连续浏览仍会积累已加载元数据；单月特别大仍可能慢或占内存。后续有界缓存需同时保证焦点和滚动位置稳定，不做未经验证的截断。

时间线主要显示当前账户自己的图库，以及设置允许的伴侣时间线；**别人仅共享给你的相册不会自动变成该账户的主时间线**，请从“相册”进入。不能仅凭空白认定照片太多。

已保留 API 读取 60 秒/单次请求 90 秒上限（不限制视频播放时长）、HTTP 400/401/403/404 分类提示及遥控器重试。未访问用户 NAS 或真实照片；静态 API 核对、合成测试和构建检查不等于电视实机验证。

连接后如某个页面提示权限不足，应只补充该页面需要的权限，不授予 `all`。

## 1.2 功能：诊断、组合筛选与缩略图缓存

本节功能已通过 1.2 的 CI 与签名验收，继续包含在 1.3 候选中；不代表 1.3 已发布或已在电视实测。1.1.1 已发布版本固定在 [release/private-1.1.1](https://github.com/z979054461/Immich-Android-TV/tree/release/private-1.1.1)。

### 手动连接诊断

设置页提供诊断入口，打开页面不会联网，按“开始”才访问你当前解锁的 Immich：先检查本地配置、ping 与版本，再检查最小元数据查询；人物检查需手动勾选。权限探针目前只对已核对的 **3.3.5** 运行，其他版本或版本无法读取会明确跳过，不误报权限不足。HTTP 400 显示请求/兼容性问题，不建议扩大权限。

探针最多读取一条元数据/人物记录，仅显示版本、耗时和固定状态，不展示或记录服务器地址、API Key、照片/人物正文或代理错误页。每次调用最长 10 秒、响应体最多 64 KiB。离开、取消、锁定或切换账户会取消请求、清理结果；新会话不能接收旧结果。图片查看权限 `asset.view` 没有被这个探针验证，会明确标为未测试。

### 日期与人物组合筛选

首页新增独立筛选页，可用遥控器选起止日期和一个或多个人物，选择“全部人物”或“任一人物”；日期条件与人物条件同时生效。人物列表仅在打开选择器后按需分页。筛选需结构化搜索 API，服务端版本至少 3.2；按 3.3.5 契约核对，不把未知返回结构当成没有照片。

每页最多 100 项，使用服务端返回的 cursor；滚动接近底部再取下一页，空页或重复项页可明确继续，失败可以重试同页，重复 cursor 会停止并提示。改变条件立即废弃旧请求和旧结果。播放器只播放当前已加载的筛选结果，不偷偷遍历完整图库。

日期按**电视当前时区**计算，包含结束日，夏令时按自然日边界处理。搜索日期使用 `fileCreatedAt`，与主时间线的 `localDateTime` 口径不完全相同；搜索可能包括服务端允许显示的伴侣时间线，因此不要把结果数当成主时间线的完全等价校验。列表虽按页读取，已经浏览的元数据仍留在本页会话内，不声称有固定总内存上限。

### 私密缩略图缓存

默认 **128 MiB**，可选关闭、64、128、256 MiB；这是全应用磁盘总额，不是每账户各占一份。设置支持单独“清空缓存”，不改变容量或打断前台账户。计入临时文件和并发预留，采用 LRU 淘汰，单项最多 4 MiB；首版仅接受 JPEG/PNG/WebP 缩略图。

只有当前解锁会话的时间线、回忆、相册/人物卡片和筛选缩略图可进入缓存；原图、视频、背景和幻灯片不缓存。数据以 AES-GCM 密文存入应用私有缓存目录，密钥随机生成且只存内存，身份包含账户、服务器、会话和缩略图类型，不使用 API Key 作加密钥匙。

锁定、切换账户、切后台或退出会立即撤销该会话的解密和交付能力并异步删除文件；进程重启会清理不能再解密的孤儿文件。宽限返回创建全新会话，因此此缓存减少的是**本次前台浏览**中的重复下载，不跨后台/重启保存可解密照片。容量修改或清空有存储代次栅栏，较早的网络任务不能随后重新填回旧缓存。关闭后仍经相同会话检查正常回源。

同一解锁会话的缩略图请求复用受限 HTTP 客户端与连接池，撤销后取消请求并释放连接。解码失败先登记内存拒绝标记，再后台核对并淘汰本次读取的确切缓存条目，失败回调不等待磁盘；下一次绑定才重新下载，不自动无限重试，也不误删较新的替换内容。

图片解码器/JVM 可能持有内存副本，不承诺绝对内存擦除，也不防御已取得 root 或应用进程控制权的攻击者。

上游宣称支持 Immich 3.0.0+；本分支按 3.3.5 的 API 接口及权限做静态核对，但在连接真实服务器和电视实测前，不宣称已完成 3.3.5 端到端兼容验证。未访问开发者/用户 NAS 或照片。

## 构建与测试

需要 JDK21、Android SDK37 和可访问官方构建依赖的网络。无需 Firebase 配置、演示密钥或作者服务配置。

单元测试还需公开的固定 [1.1.1 APK 签名样本](https://github.com/z979054461/Immich-Android-TV/releases/download/v1.1.1-private/ImmichTV-Private-1.1.1.apk)：下载到仓库外，SHA-256 必须为 `21153d9c46bf7865f3337af7e74a067f0b5bd7ff462ec53e1e693894d88630a3`，并把其绝对路径设置为环境变量 `IMMICH_UPDATE_TEST_APK`。无需私钥。缺少样本或摘要不符会明确失败，不能跳过签名测试。

```sh
python3 scripts/check_private_runtime.py
./gradlew :app:testDebugUnitTest :mediaslider:mediaslider:testDebugUnitTest :app:lintDebug :app:assembleRelease
```

无签名环境变量时 release 输出**未签名 APK，不能直接安装**。要长期覆盖升级，需通过安全流程另行配置本应用专用签名密钥，不能复用别的应用的签名授权或把私钥提交到 Git。本仓库 CI 先运行检查，在本仓库的可信分支通过后才读取专用 Secrets 签名。PR 检查不读取签名凭据。CI 只产出检查报告及签名构建产物，不自动公开发布 GitHub Release，也不向 Play Store 上传。发布在检查成功后按单次授权执行。

有权限的维护者可在自己的安全构建环境配置 `RELEASE_KEYSTORE_PATH`、`RELEASE_KEYSTORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD` 后构建签名 release。不要在日志中输出这些值。CI 的持久 Secrets 为 `RELEASE_KEYSTORE_BASE64`、`RELEASE_KEYSTORE_PASSWORD`、`RELEASE_KEY_PASSWORD` 和公开证书指纹 `RELEASE_CERT_SHA256`；Java 会按指纹定位实际别名并验证私钥签名，不依赖 PKCS12 友好名。

隐私回归测试包括真实本机回环 HTTP 服务器，验证 301/302/303/307/308 不跟随、跨域请求在 DNS 前拒绝、Key 只在单个请求头里、未配置时禁止联网。网络测试只用合成数据，不访问 NAS；签名回归使用上述固定公开 APK，验证原件及篡改 DEX 后重新计算下载摘要仍被签名拒绝。静态检查不是抓包证明；最终 APK 仍需检查合并 Manifest、运行依赖和电视实机网络行为。

## 手动应用更新的网络例外

照片、视频及 Immich API 仍只访问所配置的自有 Immich。用户已批准的唯一独立更新来源是本分支的 GitHub Releases：手动“检查更新”访问 `api.github.com/repos/z979054461/Immich-Android-TV/releases`；手动“下载”访问本仓库 `github.com` 发布资产，并仅允许重定向到 `release-assets.githubusercontent.com` 的发布资产路径。检查包含本分支的 prerelease，排除草稿、非私有版本和旧版本，不使用会漏掉 prerelease 的 `/releases/latest`。

更新客户端独立于账户网络栈，无 Cookie、令牌、API Key、Immich 地址、照片或人物信息，无正文日志，无自动重试。只有用户明确点击才联网；启动、返回前台、定时任务和安装权限返回不发起更新请求。HTTPS、重定向次数、响应时间、JSON（1 MiB）及 APK（150 MiB）都有上限。网络运营方/GitHub 仍能看到普通网络请求的来源 IP 和固定应用标识，这不是“所有流量只到自有服务器”。

下载必须匹配 GitHub 的资产大小与 SHA-256；Google apksig 对实际 APK 签名内容做验证，要求 v2/v3 和本分支固定证书 SHA-256 `276fac8da58ea9cf2ad0f32a7a3e989a9c4f46084aea351569b944027c1bb330`，包名和版本必须匹配且严格递增。PackageManager 仅用于读取包名/版本，不将提取证书误认为完整密码学校验。安装前复制到新的私有只读文件并再次验证，只有系统安装器获得单个 APK 的临时只读 URI 权限。不请求存储权限，不绕过 Android 未知来源权限或安装确认。

离开更新页面取消未完成任务并丢弃旧回调；后台仍立即撤销 Immich 会话和执行 PIN 策略。仅保存一个已验证的公共待安装 APK 和公开版本/摘要信息（离线复用有效期24小时，过期后下次手动打开时清理），返回权限页后需手动重新打开更新页并点“安装”；此时仅离线重新验证，不重复下载，也不自动安装。已交给系统的公共安装包保持可读，不因应用 onStop 提前删除，并在后续手动打开更新界面时清理过期文件。更新机制不要求额外 checksum/JSON 发布附件，只使用 APK 和 GitHub 提供的摘要。Google apksig 的 Android API24/28/37、R8 发布构建及电视安装器兼容性须通过候选 CI/设备验收，不将静态审计当作安装实测。
